# Express Pick-Up

Сервис предзаказа еды к точному времени для кафе, столовых и фуд-кортов Алматы.
Гость выбирает блюда, получает только те интервалы выдачи, на которые у кухни
есть реальная производственная ёмкость, оплачивает онлайн или на месте и
забирает заказ на отдельной стойке по номеру или QR-коду.

Оформление занимает **три шага** и не требует регистрации: статус заказа
открывается по ссылке, номеру или QR-коду.

> **О названиях заведений.** «Каганат», Coffee BOOM, Salam Bro, Del Papa,
> Bahandi, «Дареджани», Cofix и фуд-корт Mega Almaty взяты как примеры
> реальных форматов общепита Алматы, чтобы пилот выглядел предметно.
> Меню, цены, адреса и все показатели в репозитории составлены авторами
> прототипа и не являются данными этих компаний. Проект с ними не связан и не
> согласован. Перед реальным питчем адреса нужно проверить, а названия —
> согласовать с заведениями.

## Запуск

Нужен только Node.js 16+. Внешних зависимостей нет — `npm install` не требуется.

```bash
npm run hackathon    # пересоздать данные и запустить сервер одной командой
```

или по отдельности:

```bash
node scripts/seed-demo.js --fresh   # меню, история и активные заказы
node server.js                      # http://localhost:3000
```

Порт меняется переменной `PORT`:

```bash
PORT=8080 node server.js
```

Тесты — сквозные, поднимают собственный сервер на отдельной базе:

```bash
npm test
```

**Часовой пояс.** Слоты, часы работы и модель пробок считаются в локальном
поясе сервера, поэтому он должен совпадать с поясом заведения. При старте
сервис печатает определённый пояс — проверьте его при развёртывании.

При старте сервер печатает адреса в локальной сети — второй экран (кухня или
выдача) можно открыть с ноутбука, а гостевую часть с телефона: состояние
синхронизируется между ними в реальном времени.

```bash
STAFF_PIN=7391 node server.js
```

Это защита от случайного гостя, а не аутентификация: кода нет у каждого
сотрудника отдельно и действия не журналируются по людям.

## Как это устроено

```
server.js              HTTP-сервер: статика, JSON API, SSE для живых экранов
lib/capacity.js        движок производственной ёмкости — ядро сервиса
lib/geo.js             расстояния, модель пробок Алматы, время в пути гостя
lib/orders.js          жизненный цикл заказа: сборка, статусы, выдача
lib/analytics.js       отчётность пилота: KPI, пики, опоздания
lib/store.js           файловое хранилище (data/db.json) и шина событий
lib/qr.js              генератор QR-кодов (byte-режим, уровень M, версии 1–10)
lib/seed.js            стартовые заведения и меню
lib/demo.js            имитация потока с кассы и наплыва цифровых заказов
public/                четыре экрана, общий CSS и словари ru/en
```

Подробный разбор архитектуры и формул — в [docs/TECHNICAL.md](docs/TECHNICAL.md).

## Дорога гостя

Слот должен быть выполним не только для кухни, но и для гостя: интервал, до
которого невозможно доехать, гарантирует остывшее блюдо на полке. Гость
указывает район Алматы или даёт геолокацию, сервис оценивает время в пути по
локации заведения и суточному профилю загруженности дорог — и отсеивает
интервалы, до которых человек не успевает.

Пробки считаются моделью, а не живыми данными: замена на 2GIS или
Яндекс.Маршрутизацию — это одна функция `congestionFactor` в `lib/geo.js`.

## Ключевая идея

Обычный сайт предзаказа переносит очередь от кассы к выдаче. Чтобы этого не
произошло, слот выдачи в Express Pick-Up — это **обязательство кухни**, а не
запись в календаре. Заказ объёмом `W` секунд работы резервирует ёмкость не в
слоте выдачи, а в слотах *перед* ним, и предлагается гостю только если эта
работа физически размещается в окне приготовления.

```
слот 12:00 ────────────────────────────────► выдача
     ▲        ▲        ▲        ▲
   11:40    11:45    11:50    11:55     ← сюда раскладывается работа кухни
   (окно приготовления, ограничено свежестью)
```

## Материалы защиты

[docs/ЗАЩИТА.md](docs/ЗАЩИТА.md) — шпаргалка выступления: что говорить, что
нажимать по шагам, числа наизусть, ответы на вопросы жюри, чек-лист и что
делать, если сеть откажет. Рядом лежит `docs/ЗАЩИТА.pdf` для печати.

```bash
npm run pdf      # пересобрать шпаргалку в PDF
npm run slides   # пересобрать презентацию (8 слайдов, 16:9)
```

Презентация собирается **из данных работающей системы**: p90, рост выдач и
доля Express подставляются в слайды из отчёта, а не вписываются руками. В
собранной вручную версии они разошлись — слайд обещал рост на 46 %, панель
показывала 37. Жюри сверяет слайд с экраном, и такое расхождение бьёт по
доверию сильнее скромной цифры.

Перед сборкой нажмите «Подготовить демонстрацию для жюри» — иначе в слайды
попадут числа текущей базы, а не показа.

Конвертер (`scripts/md-to-pdf.js`) поддерживает подмножество разметки,
которым написаны документы проекта, и печатает через Chrome: внешних
конвертеров вроде pandoc в системе не требуется.

## Показ жюри

Страница [`/about`](http://localhost:3000/about) — самостоятельный стартовый
экран: QR на гостевой заказ, шесть шагов сценария, ссылки на все экраны с одним
заведением и код доступа персонала.

**Открывайте её по адресу в локальной сети, а не через `localhost`** — QR
кодирует текущий адрес страницы, и с `localhost` телефон его не откроет.
Страница предупреждает об этом сама. Адрес печатается при старте сервера.

В панели во вкладке «Демо» кнопка **«Подготовить демонстрацию для жюри»**
строит день из фиксированного зерна: цифры повторяются при каждом запуске,
поэтому показ можно отрепетировать. Автопилот кухни при этом выключается —
статусы двигает человек.

Кнопка также расширяет часы работы заведения на сутки: иначе вечерний показ
упёрся бы в закрытую кухню, а слотов не было бы вовсе. Исходные часы
сохраняются в настройках.

Карточка **«Попробуйте сломать наше обещание»** на `/about` даёт жюри создать
наплыв заказов и увидеть, какие именно времена закрылись и какое стало
ближайшим гарантированным. При исчерпании мощности система отказывается
принимать заказы — вместо того чтобы пообещать время и не выполнить его.

Для гарантированного результата на сцене есть отдельное действие: оно
добавляет заказы ровно до закрытия ближайшего слота, не больше двенадцати.

```bash
curl -X POST -H "X-Staff-Pin: 2468" \
  http://localhost:3000/api/demo/kaganat-abay/stress
```

## Демонстрация

Во вкладке **Демо** панели заведения:

- **Смоделировать наплыв Express** — заказы занимают ближайшие слоты, видно,
  как интервалы закрываются по мере исчерпания ёмкости кухни;
- **Добавить заказы с кассы** — живой поток walk-in, который кухня готовит прямо
  сейчас; на прогнозе появляется серый сегмент;
- **Сгенерировать день замеров** — наполняет день данными для отчёта;
- **Кухня двигает статусы сама** — автопилот для показа без участия человека.

## Где поесть рядом

В пилоте восемь точек разных форматов по Алматы: столовая, две кофейни,
экспресс-кофейня, фаст-фуд, пиццерия, грузинская кухня и фуд-корт ТРЦ. Форматы
подобраны специально: у них принципиально разная производственная ёмкость —
пицце нужна печь и семь минут, эспрессо готовится за полминуты, — и движок
слотов должен одинаково корректно работать для обоих.

По кнопке «Показать ближайшие ко мне» браузер запрашивает геолокацию, и
каталог пересортировывается по времени в пути до каждой точки с учётом пробок.
Закрытые точки уходят вниз при любом расстоянии. Если идти пешком быстрее, чем
ехать, сервис так и предлагает: до соседней кофейни это одна минута против
шести минут с парковкой.

На карте своя точка отмечена синим, точки заведений окрашены по состоянию, имя
показывается подсказкой, а по нажатию открывается карточка с переходом в меню.
Рамка карты охватывает все точки вместе с позицией гостя: иначе после
определения геолокации половина заведений уезжает за край и сравнить, что
ближе, становится невозможно.

В атрибуции карты оставлено упоминание Leaflet без вшитого в библиотеку флага.
Строка `© OpenStreetMap` обязательна: их данные используются по лицензии ODbL,
которая требует указания источника.

## Карта города: рынок вокруг пилота

По умолчанию на карте только восемь подключённых точек. Кнопка «Показать рынок
Алматы» добавляет слой реальных заведений города из OpenStreetMap — это
аргумент для защиты, а не помощь гостю, поэтому он выключен: человек пришёл
купить обед, и точки, в которых заказать нельзя, мешают ему выбрать.

В слой попадают только форматы, которым осмыслен предзаказ обеда навынос:
столовые, кафе, фастфуд, фуд-корты, пекарни и кофейни — **950 точек из 1622**.
Рестораны, бары, пабы, кондитерские и мороженое исключены: там нет обеденного
потока навынос, ради которого существует сервис, и показывать их как
потенциальных участников значило бы завышать рынок.

Точки принципиально разделены, чтобы никого не вводить в заблуждение:

| | Что это | Можно заказать |
|---|---|---|
| крупная цветная точка | заведение пилота, цвет по живому статусу | да |
| мелкая серая точка | подходит по формату, но не подключено | нет |

Данные выгружаются один раз и лежат в репозитории, поэтому карта работает без
обращения к внешнему API:

```bash
node scripts/fetch-poi.js     # обновить справочник точек города
```

Источник — OpenStreetMap через Overpass API, лицензия ODbL; указание источника
обязательно и выводится в атрибуции карты.

**Пределы масштаба.** Карта ограничена зумом 10–18: ниже город сжимается в
точку, выше тайлов просто не существует.

Точки проявляются постепенно. На обзорном виде показана разрежённая выборка —
видна плотность рынка, а не каждая вывеска; по мере приближения проявляются
остальные:

| Зум | Точек в кадре |
|-----|---------------|
| 12  | 140 |
| 14  | 350 |
| 16  | 700 |

Выборка равномерная, а не первые попавшиеся, иначе точки сбивались бы в угол
области. Подпись под картой сообщает, сколько показано из скольких.

Колесо мыши по умолчанию выключено, иначе карта перехватывает прокрутку
страницы и её невозможно пролистать. Включается нажатием на карту, о чём
написано прямо на ней.

## Живой статус заведений

Каталог показывает не расписание, а фактическое состояние на эту минуту:
открыто ли заведение, принимает ли заказы, сколько свободных интервалов
осталось и на какое время ближайшая выдача. Отдельно выводится
предупреждение, если до закрытия осталось меньше, чем нужно кухне на
приготовление.

«Открыто» и «принимает заказы» — разные состояния: кухня может работать, но
все ближайшие интервалы выбраны. Точка заведения на карте окрашивается
соответственно: зелёная — принимает, жёлтая — мест нет, серая — закрыто.

Обновление идёт и по событиям заказов, и по таймеру: открытие и закрытие
происходят по часам, а не по действию пользователя, поэтому одного потока
событий недостаточно.

## Приватность заказа

Номер заказа короткий, последовательный и называется вслух — то есть публичный
по своей природе. Поэтому по номеру отдаётся только то, что и так висит на
табло выдачи: номер, статус и время. Имя гостя, состав заказа, токен и действия
(отмена, «я на месте») доступны исключительно по приватной ссылке из заказа или
QR-коду. Поиск по номеру дополнительно ограничен по числу попыток с адреса.

## Внешние зависимости

Пакетов из npm нет вовсе. Leaflet лежит в репозитории
(`public/vendor/leaflet/`, BSD-2-Clause) и отдаётся своим же сервером: сервис
не должен зависеть от доступности чужого CDN в заведении, где падает Wi-Fi.

Единственный внешний ресурс — тайлы OpenStreetMap на гостевой странице выбора
заведения. Без них карта остаётся рабочей: точки заведений на своих местах, а
под картой появляется пояснение, что подложка недоступна. Экраны кухни, выдачи
и панели не обращаются наружу вообще.

## Письма гостю

Гость может оставить почту (необязательно) при заказе или позже — со страницы
статуса. На каждое важное событие уходит письмо со ссылкой на живой статус:
заказ принят (с временем выдачи), готов, выдан, снят заведением, неявка.
«Готовится» не рассылается — между «принят» и «готов» гостю делать нечего.
Язык письма — язык интерфейса гостя (RU/EN).

Отправка — собственный SMTP-клиент поверх TLS (`lib/mail.js`), без пакетов.
Настройки в `.env` (см. `.env.example`): `MAIL_USER`, `MAIL_PASS` (для Gmail —
пароль приложения), `MAIL_HOST`/`MAIL_PORT`. Без них письма только пишутся в
журнал — его видно в панели на вкладке «Почта», там же кнопка проверочного
письма. Ссылка в письме строится от `PUBLIC_URL`, а без него — от адреса
сервера в локальной сети, чтобы открывалась с телефона. Демонстрационные
заказы и заказы с кассы писем не получают.
